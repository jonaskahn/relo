# 🚀 v0.3.5 — 2026-11-28

### ✨ Improvements

- 🔐 The **Meta Muse Code** connection signs in with a Meta device code. Relo shows the code and approval link, then exchanges the granted account token for a Muse Model API key; the installed Muse CLI and its keychain credential are no longer needed. The key response also supplies the account id, email and tier, so the sign-in carries its own identity.
- 📊 Meta Muse quota reads the vendor's rolling and weekly usage windows from that key response, with the reported reset times. A refused token triggers a sign-in refresh and marks the account for re-authentication; a failed probe leaves the last reading alone for five minutes.
- 🧾 A Meta account with an inactive subscription can still be added. Meta sends no key then, so Relo keeps the account token until the subscription is renewed instead of refusing the sign-in.

### 🐛 Fixes

- 🔁 A half-open recovery trial is spent only on the account Relo actually selects. Choosing a healthy account no longer consumes a backup's trial, so a long rate limit on the primary can still fail over to that backup in the same request. A cooling account is skipped even when it is pinned, preferred or picked by the strategy.
- 🍎 The macOS tray no longer aborts a menu refresh. Nil strings and run-loop modes never reach AppKit, and strings passed to Objective-C stay alive across the call so the collector cannot reclaim them while they are read. A nil run-loop mode now fails instead of waiting forever.

### 🧪 Quality

- 🧪 Coverage now exercises Meta Muse sign-in and key parsing, quota windows, recovered-account failover end to end, and thread history, retention and reply retention.
